# SHINJICASE — ケース面接 × 警察ドラマ風プラクティス（モック）

米国警察捜査ドラマの体裁でケース面接を練習するアプリの **最小モック** です。  
現在は **ⅱ EVIDENCE（捜査ボード）** と **ⅲ PRIME SUSPECT（容疑者特定）** が動きます。ⅰ INTAKE は仮置きの値、ⅳ・ⅴ はプレースホルダです。

## フェーズ対応

| ケース面接 | 本アプリ（警察ドラマ） | 状態 | 画面での表現 |
| --- | --- | --- | --- |
| ⅰ 前提確認 | **INTAKE（事件受理）** | 仮置き | 定義・依頼人・TARGET の黄色いメモ3枚をボード上部に常時表示（今は固定値：売上 ×1.3／3年） |
| ⅱ 現状分析 | **EVIDENCE（捜査ボード）** | 動作 | ⅰ の指標が黒いルートカード。カードから赤い糸を引き出して証拠カードを増やし、糸に ×（仕組み）／＋（内訳）バッジ |
| ⅲ ボトルネック特定 | **PRIME SUSPECT（容疑者特定）** | 動作 | ボードで作ったカードから最大3名に赤ピン、動機を書いて CAPTAIN に提出 |
| ⅳ 打ち手立案 | **OPERATION（逮捕作戦）** | 未実装 | 容疑者ごとに作戦カードを貼る（予定） |
| ⅴ 打ち手評価 | **WARRANT（令状請求）** | 未実装 | Impact・Feasibility・Time-Span で並べ、署長が承認（予定） |
| 面接官の突っ込み | **CAPTAIN（署長）** | ⅲ のみ | 右パネルからチャレンジ。修正して再提出で **REVISE BONUS** |

上部のフェーズナビ（INTAKE › EVIDENCE › …）はクリックで行き来できます。起動時は EVIDENCE から始まります。

## EVIDENCE（捜査ボード）の使い方

1. ボード左に **黒いカード「売上」**（ⅰ で決めた指標）が最初から置かれています。
2. カード右端の **赤い丸（●）をドラッグ** すると赤い糸が伸びます。離した位置に **空欄カード** ができ、そのまま名前を入力できます（Enter で確定）。
   - 赤い丸を **クリックするだけ** なら、親の右・兄弟の下に自動で配置します。
3. 新しい糸の種類はツールバーの **「× 仕組み」／「＋ 内訳」** で選びます。
4. 作った後でも、糸の真ん中の **バッジをクリック** すると × ⇄ ＋ が切り替わります（＋ は点線の糸）。
   - × の糸の下の小札をクリックすると **増減 → 生産 → 転換 → なし** とタグが回ります。
5. カードは **ドラッグで自由に移動** できます（糸もついてきます）。
6. 名前の変更は **ダブルクリック** か、カード右下の **✎**。
7. 削除はカード右上の **✕**、またはカードを選択して **Delete キー**。子カードもまとめて消えます（ルートは消せません）。
8. ボードの内容はブラウザの localStorage に保存され、再読み込みしても残ります。**リセット** で初期状態に戻ります。

名前を入れたカード（ルート以外）は、そのまま **ⅲ PRIME SUSPECT の容疑者候補** になります（末端のカードが先に並びます）。ボードに名前入りのカードが1枚もないときは、サンプルケース（郊外ガソリンスタンド）の候補カードを使います。

## PRIME SUSPECT（容疑者特定）

1. 候補カードをクリックしてプライム容疑者にピン留め / 解除（最大 3、赤リング）
2. ピン留めした容疑者ごとに動機（一行）を入力
3. CAPTAIN に提出 → スクリプトによるチャレンジ（空・短い動機・人数・理想どおり、で文言変化）
4. チャレンジ後に編集して再提出 → REVISE BONUS 加算

## ⅰ INTAKE の今後（データ構造だけ用意済み）

`src/types.ts` の `IntakeData` と `src/data/intake.ts` の `STUB_INTAKE` が仮置きです。将来は次をプレイヤー入力に置き換えます（`status: 'stub' → 'player'`）。

- 依頼人の調書（`statement`）の曖昧な言葉をマーカーでなぞり、定義カードを書く（`definition.range`）
- 依頼人カード（`clientOptions`）から「誰からの相談か」を選ぶ
- 目標を「指標・倍率・期限」のダイヤルで入力（`target: { metric, multiplier, years }`）

TARGET の `metric` が EVIDENCE のルートカードの名前になります。

## 動かし方

```bash
npm install
npm run dev
```

ブラウザで表示された URL（通常 `http://localhost:5173`）を開いてください。

```bash
npm run build   # 本番ビルド
npm test        # ロジックテスト（CAPTAIN・捜査ボードのツリー操作）
```

## ファイル構成

- `src/App.tsx` — フェーズ切替と状態（ツリー・ピン・スコア）
- `src/components/EvidenceBoard.tsx` — 捜査ボード（SVG の糸 + 絶対配置のカード）
- `src/components/IntakeMemos.tsx` — 上部の黄色いメモ3枚
- `src/logic/evidenceTree.ts` — ツリー操作（追加・名前変更・移動・子ごと削除・× ／＋・候補化）
- `src/logic/captain.ts` — CAPTAIN のチャレンジと採点
- `src/data/` — 仮置き INTAKE、サンプルケース、フェーズ定義
