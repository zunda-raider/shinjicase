# SHINJICASE — ケース面接 × 警察ドラマ風プラクティス（モック）

米国警察捜査ドラマの体裁でケース面接を練習するアプリの **最小モック** です。  
現在は **EVIDENCE（捜査ボード）**・**OPERATION（逮捕作戦）**・**WARRANT（令状請求）** が動きます。EVIDENCE で ⅱ・ⅲ、OPERATION で ⅳ、WARRANT で ⅴ（自分で立てた評価軸に ○△✖）を行います。ⅰ INTAKE は仮置きの値です。

## フェーズ対応

| ケース面接 | 本アプリ（警察ドラマ） | 状態 | 画面での表現 |
| --- | --- | --- | --- |
| ⅰ 前提確認 | **INTAKE（事件受理）** | 仮置き | 定義・依頼人・TARGET の黄色いメモ3枚をボード上部に常時表示（今は固定値：売上 ×1.3／3年） |
| ⅱ 現状分析 | **EVIDENCE（分解と容疑者）** — 分解モード | 動作 | ⅰ の指標（売上）が一番上の黒カード。下の段へ「顧客数 × 客単価」のように分解し、必要な所だけ掘り下げる。同じ売上に対する別の分解は「切り口」タブで並べて持てる |
| ⅲ ボトルネック特定 | **EVIDENCE（分解と容疑者）** — 容疑者モード | 動作 | 同じツリーのカードに赤ピン（最大3）。右の欄に動機を書いて CAPTAIN に提出 |
| ⅳ 打ち手立案 | **OPERATION（逮捕作戦）** | 動作 | 左に番号つきのツリー（容疑者は赤丸）、右に番号ごとの作戦カード。施策は手で入力 |
| ⅴ 打ち手評価 | **WARRANT（令状請求）** | 動作 | 評価軸を自分で2〜3本入力し、OPERATION の施策に ○△✖。優先順位を自動表示、最終回答（3行） |
| 面接官の突っ込み | **CAPTAIN（署長）** | 動作 | EVIDENCE：チャレンジ＋REVISE BONUS。OPERATION：容疑者に作戦があるか。WARRANT：軸・評点の抜けを指摘、揃えば令状承認 |

フェーズナビ：INTAKE › EVIDENCE（分解と容疑者）› OPERATION › WARRANT（クリックで行き来。起動時は EVIDENCE）  
各画面の上（ナビの右端）と下に **「‹ 前のフェーズ」「次のフェーズへ ›」** ボタンがあります。WARRANT（最後）では「完了」になり、評点が揃うと「完了 — 令状承認可」と表示されます。

## EVIDENCE の使い方

### 切り口（シート）

同じ「売上」という目的に対して、ツリーはいくつも考えられます。ボードの上のタブ1枚が1つの **切り口** です。

- どの切り口も、一番上は ⅰ INTAKE の指標（**売上**）の黒カードで共通です（ここでは編集不可。INTAKE の指標が変われば全切り口のルートが一緒に変わる）。
- **＋ 切り口を追加** で新しいシート（「切り口2」「切り口3」…）ができます。
- タブの **✎** か **ダブルクリック** で名前変更（例：「顧客数×単価」「店舗数×店舗あたり売上」）。選択中でないタブも直接変えられます。Enter かほかをクリックで確定、Esc で取消、空の名前は無効（元の名前のまま）。
- タブの **✕** で切り口を削除（最後の1枚は消せない）。その切り口に刺した赤ピンも外れます。
- タブには刺した赤ピンの数（📌2 など）が出ます。

### 分解モード（ⅱ 現状分析）

ツリーは上から下へ自動で並びます。例：

```
                 売上
        ┌─────────┴─────────┐
      顧客数        ×      客単価
   ┌────┴────┐
 既存顧客  ＋  新規顧客
```

1. 一番上の **黒いカード「売上」**（ⅰ で決めた指標）の **「× 分解」**（仕組み＝掛け算）か **「＋ 分解」**（内訳＝足し算）を押すと、下の段に空欄カードが2枚できます。
2. 名前は全部手で入力します。**Enter で確定**、**Tab で右隣のカードへ**（最後のカードなら右隣に要素を追加）。
3. 3つ以上に分けたいときは、子カードの **「＋要素」** で同じ分解に要素を足します（右隣に入る）。
4. 演算子は **分解ごとに1つ**（親の分け方）。兄弟の間の **× / ＋ をクリック** すると、その分解全体が切り替わります。
   - × の分解には親の下に小札があり、クリックで **増減 → 生産 → 転換 → なし** とタグが回ります。
5. どのカードを分解するかは自由。分解しないカードはそのまま末端になります。
6. 名前の変更は **ダブルクリック** か **✎**。削除は **✕** か、カードを選んで **Delete キー**（子もまとめて消える。最後の子が消えると分解も解除。ルートは消せない・名前も変えられない）。
7. 各カード左上の **番号**（1, 2 / 1-1, 1-2 …、ルートは番号なし）は OPERATION の作戦カードの番号と同じです。並び順から自動で振られます。
8. 配置は自動（部分木の幅で計算し、重ならない）。ツリーが広く・深くなるとボードがスクロールします。
9. **例を読み込む** で2つの切り口を読み込めます：「顧客数×単価」（売上 = 顧客数 × 客単価、顧客数 = 既存顧客 ＋ 新規顧客）と「店舗数×店舗あたり売上」。**リセット** は今の切り口だけをルートだけに戻します。
10. 切り口・ツリー・施策はブラウザの localStorage（`shinjicase.evidence.v4`）に、赤ピンと動機は `shinjicase.suspects.v1` に保存されます。前の版のデータ（v3 の切り口、v2 の単一ツリー）は自動で引き継ぎ、さらに古い形式は捨てます。

### 容疑者モード（ⅲ ボトルネック特定）

1. ツールバーの **「📌 容疑者モード」** に切り替えます。
2. ボトルネックだと思うカードをクリックすると **赤ピン＋赤丸**。**全切り口の合計で最大 3**（タブを切り替えて別の切り口のカードにも刺せる）。もう一度クリックで外れます。ルートと名前が空のカードには刺せません。
3. 右の **PRIME SUSPECTS** 欄に、ピンごとの動機（一行）を書きます。どの切り口のどの経路のカードかも表示されます。
4. **CAPTAIN に提出** → スクリプトによるチャレンジ（動機が空・短い・人数・理想どおり、で文言が変わる）。
5. ツリー・ピン・動機を直して再提出すると **REVISE BONUS** が加算されます。

## OPERATION（逮捕作戦）の使い方

1. EVIDENCE で赤ピンを刺したら **「次のフェーズへ ›」**。
2. **左** に選んだ切り口のツリーが番号つき・読み取り専用で出ます。（EVIDENCE より約半分のコンパクト表示。右の作戦カード側に幅を寄せています）容疑者（赤ピン）は赤丸のまま。各箱に作戦の件数も表示。
   - 左上の **切り口** プルダウンで別のツリーに切り替え（初期値は EVIDENCE で開いていた切り口）。ツリーの編集は EVIDENCE で。
3. **右** に番号ごとの **作戦カード**（容疑者が先頭、あとは番号順）。**容疑者のみ表示** で絞り込めます。
4. カードの **「＋施策を追加」** で入力欄ができ、施策を手で入力。**Enter で次の行** を追加。1つの箱に施策はいくつでも、✕ で削除。
5. 左の箱をクリック → 右の対応カードへスクロールして強調。右のカードにマウスを乗せる／見出しをクリック → 左の箱が強調。
6. 施策は必ずどこかの箱の下にあるので「打ち手はツリー上の箱に対応する」が自然に守られます。作戦がない容疑者があると ⚠「容疑者②（1-2 新規顧客）に作戦がない」と CAPTAIN が指摘。
7. 施策は番号ではなくノードIDにひもづけて保存するので、EVIDENCE で要素を足して番号が変わっても消えません。EVIDENCE でノードを消すと、その（と子の）施策も消えます。

## WARRANT（令状請求）の使い方

1. OPERATION で施策を書いたら **「次のフェーズへ ›」**。
2. 上部の **評価軸** に名前を自分でつける（初期値は「効果」「実行しやすさ」「期間」。変更・削除可。**2〜3本**）。「＋軸を追加」で最大3本。
3. 表の行が施策、列が評価軸。各マスで **○ / △ / ✖** のどれかを選ぶ（もう一度押すと外れる）。
   - 既定は **容疑者の施策のみ**。チェックを外すと全施策を表示。
   - 複数の切り口があるときは、どの切り口の施策かも表示されます。
4. 右の **優先順位** は ○=2・△=1・✖=0 の合計で自動ソート（同点は元の順）。未評価の施策は末尾。
5. **最終回答（3行）** に優先する打ち手とその理由を書く（任意だが CAPTAIN が促す）。
6. 軸に名前があり、表示中の施策すべてに全軸の評点がつくと、CAPTAIN が「令状を承認できる」と出し、完了ボタンが「完了 — 令状承認可」になります。
7. 評価軸・評点・最終回答は `shinjicase.warrant.v1` に保存されます。OPERATION で施策を消すと、その評点も消えます。

## ⅰ INTAKE の今後（データ構造だけ用意済み）

`src/types.ts` の `IntakeData` と `src/data/intake.ts` の `STUB_INTAKE` が仮置きです。将来は次をプレイヤー入力に置き換えます（`status: 'stub' → 'player'`）。

- 依頼人の調書（`statement`）の曖昧な言葉をマーカーでなぞり、定義カードを書く（`definition.range`）
- 依頼人カード（`clientOptions`）から「誰からの相談か」を選ぶ
- 目標を「指標・倍率・期限」のダイヤルで入力（`target: { metric, multiplier, years }`）

TARGET の `metric` が EVIDENCE のツリーの一番上（ルート）の名前になります。

## 動かし方

```bash
npm install
npm run dev
```

ブラウザで表示された URL（通常 `http://localhost:5173`）を開いてください。

```bash
npm run build   # 本番ビルド
npm test        # ロジックテスト（CAPTAIN・ツリー・切り口・施策・評価軸・○△✖・移行）
```

- `src/components/WarrantPhase.tsx` — WARRANT（評価軸・○△✖ マトリクス・優先順位・最終回答）
- `src/components/TreeThreads.tsx` — ツリーの糸（EVIDENCE と OPERATION で共通）
- `src/components/PhaseSteps.tsx` — 前／次のフェーズボタン
- `src/components/SuspectList.tsx` — 赤ピンの容疑者と動機の欄
- `src/components/IntakeMemos.tsx` — 上部の黄色いメモ3枚
- `src/logic/evidenceTree.ts` — ツリー操作（分解・要素追加・名前変更・子ごと削除・演算子切替）、自動レイアウト、番号（1-1 …）、赤ピン
- `src/logic/workspace.ts` — 切り口（シート）の追加・名前変更・削除、ルートを ⅰ の指標にそろえる、全体で3本の赤ピン、施策の追加・編集・削除、保存データの移行
- `src/logic/operation.ts` — 容疑者ごとの作戦数チェック、OPERATION の CAPTAIN のセリフ
- `src/logic/warrant.ts` — 評価軸・○△✖・優先順位・WARRANT の CAPTAIN・保存
- `src/logic/captain.ts` — CAPTAIN のチャレンジと採点
- `src/data/` — 仮置き INTAKE、フェーズ定義
